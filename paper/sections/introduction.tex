A step of Bayesian training on a GPU costs what its optimiser moves. Every
parameter-sized kernel here runs at the card's memory bandwidth, so a posterior's
per-step price reduces to two counts: how many parameter-sized buffers the method keeps,
and how many times a step reads or writes each. Neither count contains the batch
size.

Four optimisation strategies are implemented over one network to make those counts
measurable. Bayes-by-Backprop \citep{blundell2015weight}, Vadam
\citep{khan2018vadam}, a learned low-rank-plus-diagonal Gaussian covariance and a
five-member deep ensemble \citep{lakshminarayanan2017simple} share a single CUDA
implementation of a GPT-2 \citep{radford2019language}: the same kernels, the same
forward and backward pass, the same batches in the same order, the same AdamW
hyperparameters, the same precision. Each arm's source file holds only what it stores
and how it updates it, and the ensemble stores no posterior, so every buffer the other
three add is attributable to their optimiser. Every region of every step is bracketed
by CUDA events at the launch sites, so each arm's Bayesian work is timed rather than
inferred as a difference against a baseline.
